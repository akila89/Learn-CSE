## Frontend (Angular)

### Style
- Standalone components only — no `NgModules`.
- Use Angular Signals for all reactive state in feature services (ADR-0010). No NgRx.
- Feature services (e.g. `WatchlistService`, `StockService`) own signals and call Supabase directly; components inject services and bind to signals in templates.
- File naming: `kebab-case.component.ts`, `kebab-case.service.ts`, `kebab-case.pipe.ts`.
- Class naming: `PascalCase`. Signal variable names: `camelCase`.
- Use `computed()` for derived state; avoid duplicating derived values as separate signals.
- Prefer named exports. No barrel `index.ts` files unless the directory has 3+ public exports.

### Architecture
- One service per domain entity (Company, Stock, Watchlist, Report, Recommendation).
- Components are dumb by default — delegate mutations and data fetching to services.
- Supabase client is injected via a singleton service; never instantiated directly in components.
- Route-level components load data on `ngOnInit` via the relevant service; use the `toSignal()` helper where async is unavoidable.
- Environment config is injected via the pre-build script (ADR-0018) — never hard-code API keys or project URLs.

## Scraper (.NET / C#)

### Style
- `PascalCase` for types and methods; `camelCase` for local variables and parameters.
- `SCREAMING_SNAKE_CASE` for constants.
- Async all the way — no `.Result` or `.Wait()` blocking calls.
- Use records for immutable data transfer objects (e.g. extracted indicator rows).
- Phases are separate classes with a single public `RunAsync(context)` method — independently unit-testable.

### Architecture — phase order (ADR-0006)
1. Refresh `cse_all_stocks` cache (weekly, if older than 7 days)
2. Load Active Stocks from Supabase
3. Scrape prices → `daily_prices`
4. Detect market holiday
5. If no new price data → skip indicators + recommendations; **always continue to report detection**
6. Compute Technical Indicators → `daily_indicators`
7. Detect and ingest new Reports → fundamentals tables
8. Generate Recommendations → `recommendations`
9. Write `scraper_runs` log row

Never reorder phases or skip step 7 — reports can be published on public holidays (ADR-0006).

### Database access
- Use Npgsql with direct PostgreSQL connection for all scraper DB writes (ADR-0007). PostgREST is for the frontend only.
- Wrap per-stock writes (prices + indicators) in a single SQL transaction.
- Bulk-upsert OHLCV data; never insert row-by-row in a loop.
- Connection string comes from environment/secrets — never in source.

### Gemini calls
- All Gemini calls (extraction + recommendation) run **sequentially** with a 4-second inter-call delay (ADR-0009).
- Never fire Gemini calls in parallel — the free tier is 15 req/min.
- On malformed JSON or unexpected signal: log, store raw response, leave previous Recommendation unchanged (ADR-0020).
- Store both raw and parsed Gemini output for every call — raw is audit/replay evidence.

## Database (Supabase / PostgreSQL)

### Migrations
- All schema changes go through Supabase CLI migration files in `supabase/migrations/` (ADR-0017).
- Never use the Supabase dashboard SQL editor for schema changes — read-only inspection only.
- Migration files are committed to source control and applied manually via `supabase db push`.
- Filename convention: `<timestamp>_<short_description>.sql` (generated by `supabase migrations new`).

### Naming
- Tables: `snake_case` plural (e.g. `companies`, `daily_prices`, `scraper_runs`).
- Columns: `snake_case`. Foreign keys: `<entity>_id` (e.g. `company_id`, `stock_id`).
- CSE-specific IDs: `cse_chart_id`, `cse_security_id` — never `stock_id` or `ticker_id`.

### Schema rules
- Every table has an RLS policy — no exceptions (CONTEXT.md: RLS Policy).
- `SELECT/INSERT/UPDATE` requires `auth.uid()` to match the single app user.
- Technical Indicators are stored denormalised: one row per Stock per day, flat columns per indicator. New indicators = `ALTER TABLE ADD COLUMN` (ADR-0004). No EAV tables for indicators.
- Company-level figures (Revenue, ROE, Debt/Equity) stored on `companies`; Stock-level figures (EPS, DPS) stored on the Stock. Conflicts across share classes for the same period are flagged, not silently resolved (ADR-0005).
- Soft-delete for Watchlist entries — set `is_active = false`, never `DELETE` (ADR-0002).
- `is_latest = false` marks superseded Reports; do not delete old Report rows.

## Testing

**Tests are mandatory — never commit new code without them.**

### Angular (Vitest)

- Every new `@Injectable` service gets a spec: public methods, signal state, and error paths.
- Every route guard gets a spec: the allow branch and every redirect branch.
- Every new component gets a spec: renders correctly, user interactions, error states.
- Spec file lives next to the source file: `auth.service.spec.ts` beside `auth.service.ts`.
- Test signal state transitions, not implementation details.
- Run before every commit — **all three must pass**:
  ```
  cd frontend
  npm run lint          # ESLint — must exit with 0 errors
  npm run format:check  # Prettier — must report no issues
  npm run test -- --watch=false  # Vitest — must exit with 0 failures
  ```

### Angular E2E (Playwright)

- E2E tests live in `frontend/e2e/`.
- Cover auth redirect flows, form interactions, and error states that require a real browser.
- Run with `npm run e2e` (requires `ng serve` running or uses the built-in `webServer` config).
- Authenticated tests require `E2E_EMAIL` and `E2E_PASSWORD` env vars — never hardcode credentials.
- E2E tests are not run in the pre-commit hook — run them manually before merging a PR.

### .NET scraper (xUnit)

- Phases are unit-tested in isolation — inject a mock DB context.
- Every public method on a service or phase class gets at least one happy-path and one error-path test.
- Use real SQL against a local Supabase instance for integration tests on DB write paths — do not mock the database for integration tests.
- Run `dotnet test` before every commit — **must exit with 0 failures**.

### General

- Test names state the expected outcome, not the mechanism: `returns_stale_when_price_older_than_last_run`, not `test_staleness_check`.
