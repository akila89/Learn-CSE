# CSE Stock Analyser

A personal decision-support tool for analysing equities listed on the Colombo Stock Exchange, generating AI-driven buy/sell recommendations for a self-selected watchlist.

## Language

### Core Entities

**Company**:
A company listed on the CSE. Owns PDF annual/quarterly reports and all fundamentals that are independent of share price (EPS, ROE, Revenue Growth, Debt/Equity, NAV). One Company may have multiple Stocks.
_Avoid_: Issuer, listed entity, security

**Stock**:
A specific tradeable share class of a Company — either ordinary voting (`.N0000`) or non-voting (`.X0000`). Owns its own price series and price-derived indicators (P/E Ratio, Dividend Yield). A Stock belongs to exactly one Company. A Stock is either Active or Inactive on the Watchlist.
_Avoid_: Security, instrument, ticker, share

**Chart ID**:
The numeric stock identifier returned by the CSE `allSecurityCode` endpoint. Used exclusively for price/chart API calls (`companyChartDataByStock`). Stored as `cse_chart_id` on the Stock.
_Avoid_: Stock ID, ticker ID

**Security ID**:
The numeric identifier returned by the CSE `companyInfoSummery` endpoint. Used for report and news API calls. Stored as `cse_security_id` on the Stock.
_Avoid_: Stock ID, company ID

**Watchlist**:
The single, user-managed set of Stocks to track. A Stock on the Watchlist is either Active (scraper collects data, UI shows it) or Inactive (scraper skips it, UI hides it, historical data preserved). Removing a Stock sets it Inactive — it does not delete data. Re-adding sets it Active and triggers a Backfill.
_Avoid_: Portfolio, holdings, favourites

**Report**:
A PDF document published by a Company to CSE — either an Annual Report (audited, full-year) or a Quarterly Report (unaudited, 3-month period). Every Report contains current-period figures, prior same-period figures, and % change for each line item. Gemini extracts all three values per line item from a single Report — no cross-report stitching is needed. Reports are ingested per Stock (the CSE API is symbol-scoped), but extracted figures are split: company-level figures (Revenue, Profit, ROE, Debt/Equity, Net Assets) are stored on the Company keyed by period; Stock-level figures (EPS, DPS) are stored on the Stock. Conflicting company-level figures across share classes for the same period are flagged for user review rather than silently resolved.
_Avoid_: Financial statement, filing, disclosure

**RLS Policy**:
A Supabase Row Level Security rule applied to every table. All tables require an authenticated session — `SELECT/INSERT/UPDATE` permitted only where `auth.uid()` matches the single app user. The anon key is public (compiled into the Angular bundle); RLS ensures it cannot read data without a valid login session.
_Avoid_: Permission, access control, auth rule

**Stock Note**:
A freeform user-written observation about a Stock, not tied to any Report or specific figure. Used for general observations that span multiple periods (e.g. "management has been consistently selling shares"). Stored at the Stock level.
_Avoid_: Comment, memo, tag

**Insight**:
A structured observation auto-generated by Gemini during Report extraction — derived from quantitative analysis of extracted figures (e.g. negative operating cash flow despite positive net income) or from qualitative content in report footnotes and annexes. Stored as a list on the Company, refreshed on each new Report ingestion. Fed into the Recommendation prompt as context.
_Avoid_: Flag, alert, warning, observation

**Company Profile**:
A structured description of a Company extracted by Gemini from its most recent Annual Report. Covers: what the business does, its sector, key revenue drivers, and notable characteristics (export vs domestic orientation, USD vs LKR revenue split, state-owned, etc.). Stored at the Company level and included in every Recommendation prompt as background context.
_Avoid_: About, description, company info

**Recommendation**:
An AI-generated buy/sell signal for a Stock, produced nightly after the price scrape. Contains a signal (BUY / ACCUMULATE / HOLD / REDUCE / SELL), confidence level, plain-English reasoning, and flagged risks. One Recommendation per Stock (not per user) — generated from a single Gemini prompt containing all extracted financial figures, computed Technical Indicators, Company Profile, Insights, and a combined summary of all users' Annotations for that Stock. No mid-generation data fetching — all inputs are read from the DB at prompt-build time. Full history retained; not overwritten nightly.
_Avoid_: Signal, alert, suggestion, prediction

**Technical Indicator**:
A price-derived metric computed by the scraper nightly and stored in a denormalised `daily_indicators` table — one row per Stock per day with flat columns per indicator (RSI, MACD line, MACD signal, SMA 50, SMA 200, Bollinger upper/mid/lower, 52-week high/low). New indicators are added as new columns via `ALTER TABLE` — no schema redesign needed.
_Avoid_: Chart indicator, signal, metric

**Fundamental Indicator**:
A financial metric derived from a Report. Split into two kinds: point-in-time indicators (P/E, Dividend Yield, Debt/Equity, ROE, NAV) sourced from the most recent Report regardless of type; and growth indicators (Revenue Growth, EPS Growth) sourced from the % change column embedded in the most recent Report. Every Fundamental Indicator is labelled with its source Report's period and audit status (Audited / Unaudited).
_Avoid_: Fundamental, financial metric, KPI

**Extraction Schema**:
The fixed JSON structure Gemini must return when processing a Report PDF. Contains named fields for all known financial line items (revenue, net_profit, eps, roe, debt_equity, nav, dps, etc.) — `null` if a field is absent from the PDF — plus an `additional_items` array of key-value pairs for notable items outside the fixed schema. The `additional_items` array is the primary source of auto-generated Insights. Both raw Gemini output and user-confirmed output are stored — raw for prompt improvement auditing, confirmed as the source of truth for indicators and recommendations.
_Avoid_: Output format, response schema, parsed data

**Annotation**:
A field-level note attached to a specific extracted figure within a specific Report. Has two sources: a Report Footnote (extracted by Gemini from asterisks, footnotes, or annexes in the PDF — the company's own qualification of a figure) and a User Annotation (added manually during the review step). Both are stored per field per Report. When building the Recommendation prompt, all Annotations for a Stock across all users are combined and sent inline with their associated figure.
_Avoid_: Comment, note, flag

**Scraper Run**:
A single execution of the nightly GitHub Actions workflow. Scheduled at 3 AM Sri Lankan time (UTC+5:30 → cron `30 21 * * *` UTC), after market close (2 PM SLT) and before market open (9:30 AM SLT). Each run writes a log row recording timestamp, status (success/partial/failed), stocks attempted, stocks failed, and error detail. Readable from the Scraper Control screen.
_Avoid_: Job, workflow, sync

**Stale**:
A Stock whose `last_price_scraped_at` is older than the previous trading day's 3 AM SLT Scraper Run — checked only on trading days after 9 AM SLT. A trading day is any weekday that is not a Sri Lankan public holiday (CSE closes on all Sri Lankan public holidays). Holiday detection is self-detecting: the scraper compares the latest price date returned by the CSE API against what is already stored. If a weekday scrape returns no new data, it logs "no trading detected — possible holiday" and suppresses the stale badge. If the API call itself fails (distinct from returning no new data), it logs as an outage. A hardcoded `holidays.json` is the fallback if self-detection proves unreliable. A Stale Stock shows a warning badge and a human-readable "Prices as of…" timestamp on its card.
_Avoid_: Outdated, expired, missing

**PDF Retention**:
Report PDFs are stored in Supabase Storage after download. PDFs older than 3 years are eligible for deletion. Extracted data in PostgreSQL is kept indefinitely — only the source PDFs are pruned. Re-extraction from stored PDFs is possible when the Gemini prompt improves.
_Avoid_: Archive, cleanup, purge

**Backfill**:
The process triggered when a Stock is reactivated — fetches missing price data and any reports published during the inactive period. Price backfill is limited to ~1 year by the CSE API (`period=5`); gaps older than 1 year are permanent. Report backfill is complete regardless of gap length.
_Avoid_: Sync, refresh, historical load

## Example Dialogue

> **Dev:** A new quarterly report just appeared for COMB.N0000. What happens?
>
> **Domain expert:** The Scraper Run detects it via the `financials` endpoint — the PDF path is new. It downloads the PDF to Supabase Storage, sends it to Gemini with the Extraction Schema, and gets back raw structured output. Company-level figures like Revenue go to the Company; Stock-level figures like EPS go to the COMB.N0000 Stock. If COMB.X0000 is also on the Watchlist, we call `financials` for that symbol too — if it returns the same report, we deduplicate company-level figures and only store the COMB.X EPS separately.
>
> **Dev:** What if Gemini flags something unusual in the report?
>
> **Domain expert:** Gemini populates `additional_items` with anything outside the fixed schema — say, "operating cash flow turned negative despite positive net income." That becomes an Insight on the Company. The user reviews the raw extraction in the UI, corrects any wrong figures, and can add a User Annotation to a specific field — like "EPS includes one-off gain, not recurring." The confirmed output is saved alongside the raw.
>
> **Dev:** Does that annotation affect the Recommendation tonight?
>
> **Domain expert:** Yes. The nightly Scraper Run builds the Gemini prompt for COMB.N0000 using the confirmed figures, the Insight, and the Annotation inline against the EPS field. The Recommendation it generates will explicitly account for the one-off. It's stored as a new Recommendation row — the previous one is not overwritten.
>
> **Dev:** What if COMB.N0000 was Inactive on the Watchlist last month — do we have a gap in price data?
>
> **Domain expert:** Yes, up to 1 year can be recovered via Backfill when the Stock is reactivated. Anything older than 1 year is a permanent gap — the CSE API doesn't go further back. The Report backfill is complete regardless — the `financials` endpoint returns the full history.
