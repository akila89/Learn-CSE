# CORS headers required on all Edge Functions called from the browser

All three Edge Functions (`trigger-scraper`, `extract-report`, `resolve-stock`) are invoked directly from the Angular SPA running in the user's browser. Browsers send a CORS preflight `OPTIONS` request before any cross-origin `POST` — without explicit `Access-Control-Allow-Origin` and `Access-Control-Allow-Headers` headers in the response, the actual request is blocked before it reaches the function body. Each Edge Function handles the preflight by returning a `200` response with `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Headers: authorization, x-client-info, apikey, content-type`, and `Access-Control-Allow-Methods: POST, GET, OPTIONS` when the request method is `OPTIONS`. A shared `corsHeaders` constant is extracted into `supabase/functions/_shared/cors.ts` and imported by all three functions so the header values stay consistent. The anon key is already compiled into the Angular bundle and is public by design — `Allow-Origin: *` does not weaken security here; RLS policies on the database and session validation inside each function are the actual access controls (see ADR 0011).
