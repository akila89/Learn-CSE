# Holiday detection is self-detecting with a hardcoded JSON fallback

The scraper must distinguish three weekday outcomes: new price data available (normal trading day), no new data because the market was closed (public holiday), and no data because the CSE API failed (outage). These must not be conflated — a holiday must suppress the Stale badge on all stocks for that day; an outage must not.

The primary mechanism is self-detection: after calling `companyChartDataByStock` for any stock, the scraper compares the latest returned price date against the most recent date already stored in `daily_prices`. If the API call succeeds but the latest returned date equals the stored date, the scraper logs "no trading detected — possible holiday" for that run, writes `status = holiday` to the `scraper_runs` row, and exits without marking any stock as failed or stale. If the API call itself fails (network error, non-200, malformed response), the scraper logs the failure separately as `status = failed` and the affected stocks are eligible for the retry mechanism (see ADR 0008). Only one stock needs to be checked to determine the holiday/outage split — if the first stock's API call succeeds but returns no new data, the run is treated as a holiday without calling the remaining stocks.

The fallback is a `holidays.json` file in the scraper repository listing Sri Lankan public holidays for the current and next calendar year by date. It is used only when self-detection produces a false positive or negative — for example, if the CSE API returns stale cached data on a trading day, the JSON list overrides the self-detected result. The JSON file is updated once per year (typically in January) as a routine maintenance task. Self-detection is preferred over the JSON list because it requires no advance knowledge of holidays and handles ad-hoc closures (e.g. unexpected government-declared holidays) without a code change.

The Stale badge shown on stock cards is suppressed for any day where the `scraper_runs` row records `status = holiday`. Stale detection only runs on weekdays after 9 AM SLT and compares `last_price_scraped_at` against the most recent non-holiday run, not the calendar date.
