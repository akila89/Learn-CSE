# Supabase Edge Function for manual PDF extraction

When a user manually uploads a report PDF, Gemini extraction is performed by a Supabase Edge Function (`extract-report`) rather than the .NET scraper. The scraper holds the Gemini API key in GitHub Actions Secrets — inaccessible to the Angular frontend. Triggering the scraper via `workflow_dispatch` and polling for the result would introduce an unacceptable delay in the upload review flow. Instead, a dedicated Edge Function holds the Gemini API key as a Supabase secret, accepts a Supabase Storage path from the authenticated Angular app, calls Gemini, and returns the structured extraction immediately. The Gemini API key is stored in both GitHub Actions Secrets (for the scraper) and Supabase Edge Function secrets (for manual uploads) — two separate secret stores for two separate execution contexts.

**Integration with stub rows (ADR 0022):** When the scraper has already created a `download_failed` stub row for a report (i.e. detection succeeded but CDN download failed), manual upload targets that existing row — it fills in `pdf_path`, triggers extraction via this Edge Function, and sets `ingestion_status = 'stored'`. This keeps `cse_report_id` on the row so the scraper does not re-attempt download on the next run. If no stub row exists (user is uploading a report the scraper has not detected), a new `reports` row is created with `cse_report_id = null`.
