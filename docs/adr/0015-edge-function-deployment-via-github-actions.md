# Edge Functions deployed via GitHub Actions on push to main

The three Supabase Edge Functions (`trigger-scraper`, `extract-report`, `resolve-stock`) are deployed automatically by a GitHub Actions workflow in the frontend repository whenever changes are pushed to the main branch. The workflow uses the official `supabase/setup-cli` action, authenticates with a `SUPABASE_ACCESS_TOKEN` secret, and runs `supabase functions deploy` targeting the project identified by a `SUPABASE_PROJECT_REF` secret. This keeps deployments repeatable and version-controlled alongside the function source code — no manual `supabase functions deploy` commands and no risk of the production Edge Function drifting from what is in source control. The Edge Function source lives in `supabase/functions/` within the frontend repository, co-located with the Supabase migration files (see ADR 0017). The scraper repository (public, .NET) remains separate — it has no knowledge of Edge Functions. The two GitHub Actions secrets required (`SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`) are distinct from the scraper's secrets (`SUPABASE_SERVICE_KEY`, `GEMINI_API_KEY`) and are stored in the frontend repository settings.
