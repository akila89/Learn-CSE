# Angular environment variables injected by a pre-build Node script on Vercel

The Angular build requires `supabaseUrl` and `supabaseAnonKey` to be present in `src/environments/environment.prod.ts` at compile time — Angular's `fileReplacements` in `angular.json` substitutes this file during a production build. Rather than committing real credentials or using a custom webpack plugin, a lightweight Node script at `scripts/set-env.js` reads `process.env.SUPABASE_URL` and `process.env.SUPABASE_ANON_KEY` and writes `environment.prod.ts` before the Angular compiler runs. The Vercel build command is set to `node scripts/set-env.js && ng build --configuration production`. The two variables are configured in the Vercel project's environment variable settings (not in the repository). `src/environments/environment.prod.ts` is listed in `.gitignore` so the generated file is never committed. The local development file `src/environments/environment.ts` contains placeholder values and is also gitignored; developers populate it manually once from the Supabase project dashboard. This approach requires no additional build tooling beyond what is already present in a standard Angular CLI project.
